# 要件定義書：視覚情報の有無によるボール捕捉特性の比較分析

スポーツデータ科学 第7回宿題 / フットサル パス回し視線分析

---

## 0. 全体設計

### 研究的問い（RQ）

**視覚情報の有無は、対象（ボール）を頭部正面（および視線）の中心付近に保持する能力にどう影響するか。**

| 番号 | サブ問い | 対象条件 |
|------|----------|----------|
| RQ1 | 目隠しあり条件で、ボールはフレーム中心（頭部正面方向）からどれだけ・どのように離れるか | 目隠しあり（GoPro） |
| RQ2 | 目隠し無し条件で、ボールはフレーム中心 / 視線(gaze) からどれだけ離れるか。視線と頭部方向のどちらが先にボールへ向くか | 目隠し無し（Tobii） |
| RQ3 | 2条件を比較したとき、視覚ありの方がボールを中心近くに・より安定して保持できているか | 両条件比較 |

### 仮説

- H1：視覚あり条件のほうが「ボール⇔中心」距離の中央値・ばらつき（SD/IQR）が小さい（＝より安定してボールを正面に保持）。
- H2：視覚あり条件では gaze がフレーム中心よりボールに近い（＝視線が頭部より能動的にボールを追う）。

### 前提・制約（3コード共通）

1. **デバイス非対称性**：GoProは頭部方向（フレーム中心）のみ取得、gazeなし。Tobii Pro Glasses 3 はシーンカメラ + gaze を取得。→ 比較は「ボール⇔フレーム中心」を共通軸とし、gaze関連は視覚あり条件の追加分析とする。
2. **空間スケール差**：GoPro（広角・魚眼歪み）と Tobii（シーンカメラ FOV ≈ 95°）でFOV・解像度が異なる。**ピクセル距離を直接比較しない**。視野角[度]または画面正規化座標へ変換して揃える。
3. **時間スケール差**：両機材で fps が異なる可能性。gaze は動画より高サンプリング（50/100Hz）。→ タイムスタンプで整列・リサンプル。
4. **ボール検出**：スライドの**既存フットサル用YOLOカスタムモデル**（mAP@50 86.2%）を流用する想定。フォールバックとして色ベース検出（HSV閾値）を用意。
5. **サンプル規模**：試計測のため少数。→ 記述統計を主、推測統計は補助かつ前提（独立性・正規性・少数例）の注意書きを必須とする。

### ファイル構成（想定）

```
project/
├─ code1_gopro_ball_center.py      # 目隠しあり：ボール⇔中心
├─ code2_tobii_ball_gaze.py        # 目隠し無し：ボール⇔中心 & ⇔gaze
├─ code3_compare_visualize.py      # 比較・可視化
├─ config.yaml                     # 共通設定（閾値・FOV・パス等）
├─ models/ball_yolo.pt             # YOLO重み
└─ outputs/                        # CSV・図・動画
```

## 1. コード①：目隠しあり（GoPro）ボール⇔中心 距離算出

`code1_gopro_ball_center.py`

### 目的
目隠しあり条件のGoPro動画から各フレームのボール位置を検出し、フレーム中心（＝頭部正面方向の代理）からのずれ（距離・方向）を時系列で算出する。

### 入力
- GoPro動画ファイル（.mp4）
- YOLO重みファイル（ball クラスを含む）
- （任意）カメラ内部パラメータ or 水平FOV値 … 魚眼歪み補正・視野角換算に使用
- 設定：信頼度閾値、ballクラスID、出力ディレクトリ、中心保持の判定閾値

### 処理フロー
1. 動画読み込み、fps・解像度（W,H）取得
2. （任意）魚眼歪み補正（`cv2.fisheye.undistortImage` 等）
3. フレームごとにYOLO推論 → ball バウンディングボックス取得
4. 複数検出時の採用ルール：信頼度最大、または直前フレーム位置に最も近いものを選ぶ（簡易トラッキング）
5. ボール中心 (cx, cy) = bbox中心を算出
6. フレーム中心 (W/2, H/2) との差分ベクトル (dx, dy)、ユークリッド距離 `dist_px` を計算
7. 正規化距離 `dist_norm`（対角長で割る）、（FOV既知なら）視野角 `dist_deg` を算出
8. 未検出フレームは NaN として記録（線形補間はオプション、補間有無のフラグを残す）

### 出力
- **per-frame CSV**：`frame_idx, time_sec, detected, ball_x, ball_y, conf, dx, dy, dist_px, dist_norm, dist_deg`
- **サマリー（CSV/JSON）**：検出率、距離の平均/中央値/SD/最大、**中心保持率**（dist が閾値以内のフレーム割合）
- （任意）検証用オーバーレイ動画／代表フレーム画像（ボール枠＋中心点＋中心からの線）

### 考慮事項
- 中心保持率の閾値は度 or 正規化距離で定義し config に切り出す
- 例外：検出ゼロ動画、破損フレーム、ボールが画面外のフレーム
- 性能：GPU有無の切替、長尺動画のフレームスキップ／バッチ推論オプション

## 2. コード②：目隠し無し（Tobii）ボール認識 & gaze距離算出

`code2_tobii_ball_gaze.py`

### 目的
目隠し無し条件のTobiiシーン動画でボールを検出し、フレーム中心 と 視線点(gaze) のそれぞれからの距離を算出する。

### 入力
- Tobii シーンカメラ動画
- Tobii gaze データ（gazedata / tsv：`timestamp, gaze2d.x, gaze2d.y`（0–1正規化座標）, validity 等）
- YOLO重みファイル
- 動画とgazeの同期情報（共通タイムスタンプ or オフセット）
- 設定：信頼度閾値、ballクラスID、AOI判定方法、出力先

### 処理フロー
1. 動画読み込み（fps・W,H）、gazeデータ読み込み
2. **タイムスタンプ整列**：gaze（高サンプリング）を各フレーム時刻へ最近傍 or 区間平均でリサンプル
3. フレームごとにYOLO推論 → ボール中心 (cx, cy)
4. gaze正規化座標 → 画素座標へ変換（×W, ×H）
5. 距離計算：
   - `dist_ball_center`（ボール ⇔ フレーム中心）… ①と同一定義（共通軸）
   - `dist_ball_gaze`（ボール ⇔ 視線点）
6. **AOI判定**：gaze点がボールbbox内にあるか（True/False）
7. 未検出ボール・無効gaze（瞬き等 validity NG）は NaN/除外フラグで記録

### 出力
- **per-frame CSV**：`frame_idx, time_sec, detected, ball_x, ball_y, conf, gaze_x, gaze_y, gaze_valid, dx_center, dy_center, dist_ball_center_px, dist_ball_center_deg, dist_ball_gaze_px, dist_ball_gaze_deg, gaze_on_ball`
- **サマリー**：ボール検出率、gaze有効率、各距離の平均/中央値/SD、**視線がボール上にある割合（AOIヒット率）**
- （任意）検証用オーバーレイ動画（ボール枠＋中心点＋gaze点を別色で）

### 考慮事項
- 座標系の統一（Tobii 0–1正規化 ⇔ ピクセル ⇔ 視野角）を関数化し①と共有
- gaze欠損区間の扱い（除外 vs 補間）を明示
- 動画とgazeのfps差・ドリフトに対する整列誤差の確認

## 3. コード③：2条件の比較・分析補助 & 可視化

`code3_compare_visualize.py`

### 目的
①②の出力CSVを読み込み、デバイス差を吸収した共通指標で2条件を比較・可視化し、RQ1–3への示唆を出す。

### 入力
- コード①の per-frame CSV ＋ サマリー
- コード②の per-frame CSV ＋ サマリー
- 設定：共通指標（度 or 正規化）、時間整列方法、検定の有無、図の出力先

### 処理フロー
1. 両CSV読み込み、条件ラベル付与（`blindfold` / `vision`）
2. **共通指標へ統一**：`dist_ball_center` を視野角[度] か正規化距離に揃える（FOV差を吸収）
3. 時間整列（必要に応じてパス周期ごとに切り出し／比較区間をトリミング）
4. **記述統計**（条件別）：mean / median / SD / IQR / 中心保持率
5. **分布比較**：ヒストグラム / KDE / 箱ひげ図
6. （補助）**統計検定**：分布比較に Mann–Whitney U など。※サンプル小・観測の独立性に関する注意書きを出力に必ず添える
7. **視覚あり条件の内部比較**：`dist_ball_center` vs `dist_ball_gaze`（頭部方向と視線、どちらがボールに近いか）

### 可視化（出力図）
- 条件別 **箱ひげ図**（ボール⇔中心 距離）※スライドp45の集計図のスタイルに合わせる
- **時系列重ね描き**（距離 vs 時間、条件で色分け）
- **ヒストグラム / KDE**（条件別）
- フレーム上の **ボール位置2Dヒートマップ**（条件別、中心保持の偏りを可視化）
- 視覚あり条件：**ボール / 中心 / gaze の関係図**（gazeが先行するかの確認）

### 出力
- 図（PNG）一式
- 統計サマリー表（CSV）：条件別の各統計量＋検定結果＋注意書き
- （任意）簡易レポート（Markdown）

### 考慮事項
- **日本語フォント**設定（matplotlib のフォント指定 or japanize-matplotlib）を最初に行う
- 図のスタイル・配色を統一（条件で固定色）
- 比較の妥当性に関する限界（デバイス差・サンプル数・観測研究）を図注 or レポートに明記

## 4. 確認したい前提（設計を固めるための論点）

以下は仮で置いた前提。違っていれば修正する。

1. **「真ん中のカメラの中心」= 頭部装着シーンカメラのフレーム中心**（＝頭部正面方向の代理）という理解でよいか。
2. **目隠しあり条件は GoPro（gazeなし＝頭部方向のみ）** で確定か。両条件をアイトラッカーで揃える選択肢もあるが、その場合は仕様が変わる。
3. **比較の主指標は視野角[度]換算で揃える**方針でよいか（デバイスFOV差を吸収するため推奨）。難しければ画面正規化距離で代替。
4. **ボール検出は既存フットサルYOLOカスタムモデルを流用**でよいか。汎用YOLO/色検出から始める場合は精度・前処理の要件を追記する。
